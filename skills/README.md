# ספריית סקילים ל-Copilot · ואלור Toolkit

ספריית סקילים מותאמים ל-**Copilot ב-PowerPoint וב-Excel**, בנויה לארגונים ישראליים.
כל סקיל כאן נכתב לפי הכללים שאומתו חי בטננט של ואלור ב-1.9.2026 — ראו
[`../copilot-skills-practice.md`](../copilot-skills-practice.md) לפרקטיקה המלאה.

> **הפורמט הוא תקן פתוח** — [Agent Skills](https://agentskills.io/specification),
> שנוצר ב-Anthropic, שוחרר כתקן פתוח, ומיושם היום ב-**46 כלים**: ‏Claude,
> ‏ChatGPT/Codex, ‏Gemini CLI, ‏GitHub Copilot, ‏VS Code, ‏Cursor, ‏JetBrains Junie,
> ‏Databricks, ‏Snowflake ועוד. אותו `SKILL.md` נייד ביניהם.
>
> **מה שמשתנה בין המוצרים הוא המיקום.** לכל אפליקציה תיקייה משלה, וסקיל
> בתיקייה הלא נכונה פשוט לא ייטען — בלי שגיאה. שימו לב במיוחד:
> ‏**GitHub Copilot ו-M365 Copilot הם שני מוצרים שונים** עם תיקיות ורישיונות נפרדים.

## תחזוקה שוטפת — התקנה בפקודה אחת

```bash
python copilot-skills/install.py                  # מה ישתנה, בלי לגעת
python copilot-skills/install.py --apply          # התקנה/עדכון
python copilot-skills/install.py --apply --prune  # וגם מחיקת מה שכבר לא בריפו
```

מנתב כל סקיל לתיקייה של האפליקציה הנכונה, ממיר CRLF ל-LF (git הופך אותם
ב-checkout), ואידמפוטנטי — ריצה שנייה מדווחת `0 changes`.

**זה מחליף העתקה ידנית.** בהעתקה ידנית נופלים על שלושה דברים בו-זמנית:
תיקייה של האפליקציה הלא נכונה, שורות CRLF, וסקילים ישנים שנשארו מאחור —
וכל השלושה נכשלים **בשקט**.

**אחרי כל התקנה:** בכל אפליקציה `Manage skills` -> `Custom skills` -> **`Refresh`**.
לא צריך לסגור את האפליקציה.

**ניתוב:** `variance-analysis` ו-`exec-email` -> Excel. כל השאר -> PowerPoint.
לשינוי, הוסיפו לסקיל שורה `<!-- app: excel -->`.

## התקנה ראשונית — 4 שלבים

1. **צרו את תיקיית הסקילים פעם אחת:**
   בחלונית Copilot של PowerPoint → `...` → `Manage skills` → `Custom skills` → `Create OneDrive folder`

2. **מצאו אותה ב-OneDrive:**
   ```
   OneDrive → Documents → מסמכים → Copilot → Microsoft PowerPoint → skills
   ```

3. **העתיקו לשם את תיקיית הסקיל** (התיקייה כולה, לא רק הקובץ).

4. **`Manage skills` → `Custom skills` → `Refresh`.** ואז הפעילו את הסקיל במתג.
   **אין צורך לסגור את האפליקציה** — יש כפתור Refresh, וזה מה שמיקרוסופט מתעדת.

### ⚠️ סקילים של Excel לא הולכים לתיקייה של PowerPoint

שני סקילים בספרייה — `variance-analysis` ו-`exec-email` — הם **של Excel**.
לכל אפליקציה יש תיקיית סקילים משלה. סקיל Excel שיושב בתיקייה של PowerPoint
**לא ייטען, ולא תקבלו על כך שום הודעה.**

חזרו על שלב 1 **מתוך Excel**. התיקייה שתיווצר (אומת 2.9.2026):

```
OneDrive → Documents → מסמכים → Copilot → Microsoft Excel → skills
```

קופיילוט שותל שם `README.md` רשמי ותיקיית דוגמה `make-calendar.example`.
**שווה לקרוא את שניהם** — זה התיעוד הכי מדויק שיש לפורמט.

**אם הוא לא מופיע — עברו על טבלת התקלות למטה לפני שתחפשו במקום אחר.**

| # | כלל | התסמין כשמפרים |
|---|---|---|
| 1 | הקובץ נקרא **`SKILL.md`** — אותיות **גדולות** | `Required skill information is missing` |
| 2 | שם התיקייה **זהה** ל-`name` שב-frontmatter | הסקיל לא מופיע, בלי שגיאה |

> ‏`skill.md` יושב בתיקייה, נראה לעין, ו"לא קיים" מבחינת הכלי.
> שינוי שם דורש שני שלבים: `skill.md` → `_tmp.md` → `SKILL.md`.

## איפה עובר הגבול של Copilot — נמדד, לא משוער

| יכולת | מצב |
|---|---|
| יישור פסקה וכיווניות RTL | ✅ **כן.** 20/20 פסקאות, בשלוש ריצות עצמאיות |
| עריכת תוכן ממוקדת | ✅ תיקן בדיוק 2 רווחים בלועים, לא נגע ב-18 האחרים |
| **איתור עצמאי** של מה שצריך לתקן | ✅ מצא את שני הרווחים **בלי** שנאמר לו איפה |
| כיבוד הוראה שלילית | ✅ "אל תיגע בשקפים קיימים" — קוים |
| סימון שפה ברמת run | ❓ לא נבדק — ולכן `rtl_repair.py` עושה את זה |
| גודל גופן, ניגודיות, טקסט חלופי | ❌ אינו רואה אותם |

> **מה שסקיל לא צריך לעשות, גם כשהוא יכול:** במצגת הבדיקה שתלנו תאריך הפוך
> (`2026.9.1` במקום `1.9.2026`). הסקיל **לא נגע בו** — ונכון שכך.
> ‏`3.4.2026` הוא רביעי במרץ או שלושה באפריל? תיקון "הגיוני" של תאריך
> משנה נתון עסקי בשקט. הסקיל מדווח על מספר חשוד ואינו מתקן אותו.

> **איך נמדד:** ‏[`rtl-fingerprint.py`](rtl-fingerprint.py) קורא את ה-XML וסופר
> מה באמת יש בקובץ, לפני ואחרי. הסקיל מדווח על עצמו — זו טענה, לא ראיה.
> הכלי הזה כבר תפס **דיווח כישלון כוזב** ("Copilot לא יכול לשנות עיצוב") שהיה
> הנחה שגויה שלנו, לא של הכלי.

### שני כלים לצד הסקילים

```bash
python rtl-fingerprint.py deck.pptx                     # מדוד לפני
python rtl-fingerprint.py deck.rtl-before.json deck.pptx  # השווה אחרי
python rtl_repair.py deck.pptx --in-place                # תיקון RTL מלא
```

**למה `rtl_repair.py` קיים בנוסף לסקיל:** רווח בין מילה **לטינית** למילה עברית
ייראה בלוע בהצגת המצגת גם כשהוא קיים בקובץ — `CoPilot בתוך` יוצג `CoPilotבתוך`.
זה ארטיפקט דו-כיווני, לא רווח חסר.

מה שנמדד ב-2.9.2026:

| ניסיון | גבול ספרה↔עברית | גבול אנגלית↔עברית |
|---|---|---|
| רווח רגיל | ❌ | ❌ |
| רווח קשיח `U+00A0` | ✅ | ❌ |
| **סימון שפה ברמת run** | ✅ | ✅ |

‏`rtl_repair.py` מיישם את השלישי, אידמפוטנטי, ואומת מול המרנדר של PowerPoint.

## שלושת העקרונות שכל סקיל כאן מקיים

הסקילים בספרייה לא נכתבו כ"פרומפטים ארוכים". כל אחד מקיים שלושה כללים:

**1 · ניסוח** — הסקיל אומר בדיוק מה לעשות, על איזה בסיס, ואיפה.
לא "שפר את המצגת" אלא "לכל שקף שיש בו יותר משש שורות, קצר כל שורה
ל-12 מילים לכל היותר, והעבר את מה שנחתך להערות הדובר".

**2 · קשר** — הסקיל לא מניח מידע שאין לו.
כשחסר נתון הוא **מבקש אותו** במקום להמציא. סקיל שממציא מספר גרוע מסקיל שלא רץ.

**3 · בדיקה** — כל סקיל מסיים בהודעה שאומרת **מה השתנה בפועל**, ובמספרים.
לא "בוצע" אלא "עודכנו 14 פסקאות ב-6 שקפים". בלי זה אי אפשר לדעת אם משהו קרה.

## גבולות — לקרוא לפני שמחלקים לארגון

**סקילים הם אישיים.** רק החשבון שיצר אותם רואה אותם. אין שיתוף, אין הפצה ארגונית,
אין ניהול מרכזי. הפצה = כל אחד מעתיק לעצמו את התיקייה.

**סקיל שעורך — עורך באמת.** אימתנו: סקיל שהתבקש להוסיף שקף הוסיף אותו,
עם הכותרת והתוכן המדויקים, ולא נגע בשאר. זה עובד — ולכן זה גם מסוכן.

**AutoSave משנה את רמת הסיכון:**

| מצב | מה קורה אחרי שסקיל עורך |
|---|---|
| ‏AutoSave **כבוי** | השינוי בזיכרון בלבד. הקובץ בדיסק לא נגע עד שמירה ידנית. |
| ‏AutoSave **דלוק** | השינוי **נשמר מיד**. אין חזרה מעבר ל-Undo. |

**כלל:** סקיל עריכה חדש — להריץ **פעם ראשונה על עותק**, לא על המקור.

**דורש רישיון M365 Copilot.** לא עובד על השכבה הכלולה (Copilot Chat).

## אימות — שתי שכבות

### שכבה 1 · האם הסקיל ייטען

```bash
python copilot-skills/validate.py
```

בודק את ארבעת הכללים — כולל רישיות שם הקובץ, שאותה Windows לא יראה לכם.
יוצא עם קוד 1 אם משהו לא יעבור.

**אין Python על התחנה?** (מצב נפוץ בתחנות קצה ארגוניות.) שורת PowerShell
שתופסת את שני הכללים הקטלניים:

```powershell
Get-ChildItem -Directory | ForEach-Object { $n=$_.Name; $f=Get-ChildItem $_.FullName -Filter *.md | Where-Object Name -ceq 'SKILL.md'; if(-not $f){ "FAIL $n : no SKILL.md (check casing)" } elseif(-not ((Get-Content $f.FullName -Raw) -match "(?m)^name:\s*$([regex]::Escape($n))\s*$")){ "FAIL $n : name does not match folder" } else { "ok   $n" } }
```

### שכבה 3 · האם הסקיל באמת עשה משהו

**זו השכבה שאסור לדלג עליה.** כל סקיל כאן מסיים בדיווח מספרי —
אבל **הדיווח הוא של המודל על עצמו, והוא אינו ראיה.**

בעבודה שממנה נולדה הספרייה הזו התקבל הדיווח `62 מתוך 62 עודכנו`
מכלי שרץ על מצגת שכולה תמונות ולא היה בה מה לעדכן. הדיווח היה מדויק
מבחינה טכנית וחסר משמעות לחלוטין.

**אחרי הרצה ראשונה של כל סקיל עריכה:**

1. פתחו **שניים-שלושה** מהשקפים שהסקיל דיווח שטיפל בהם
2. ודאו בעיניים שהשינוי אכן שם, ושהוא נכון
3. ודאו ששקף שהסקיל הבטיח **לא** לגעת בו אכן לא נגע

רק אחרי שעברתם את זה — הסקיל מוכן להפצה בארגון.
